> 一句话总结：这周从一台空的 Mac 起步，两天内把第一期三个模型页迁到新页面框架。最大的收获是两次「检查全绿、需求没完成」之后定下的规矩：进度和完成度都要能被机器判，人只验机器验不了的。

## 0. 这周在做什么

这是我换到 macOS 后的第一周，一切从一台空机器开始。

前两天在前端：把模型详情页从旧写法迁到团队的新页面框架，第一期三页，文本、图像、视频各一。后半周转到后端：先给一个语音合成模型做上线前调研，只出方案；再接一个声音复刻接口，并给「音色设计 + 声音复刻」的统一接口做上游实测。周四、周五没有开发工作。

工作大致分三块：搭环境和顺手写的工具、页面迁移、第一次碰后端接入。下面按这个顺序讲。

## 1. 环境：绕开 Homebrew，顺手写了个会话检索工具

第一天 GitHub 完全不通，Homebrew 的官方安装脚本拉不下来。我没有死磕，改成从各工具的官网下 arm64 安装包，用 `ditto` 拷进 `/Applications`。当前用户在 `admin` 组，这个目录可写，全程没用 sudo。pnpm 走 corepack 装。

目录按 `work`、`personal`、`playground` 三层分，zsh 里配了几个跳转别名。这个分法后来证明有用：第二周多任务并行时，在 `work` 下按任务再分一层就行。

同一天还写了一个小工具，检索本机所有 Claude Code 历史会话：支持多词 AND、正则、时间窗、按项目和角色过滤。写它的原因很实际。每天的日报要从会话里还原时间线，而现成的列表按「最后活动」排序，看不出「昨天开始、今天还在用」的会话。第二天用下来，又补了按本地日历日过滤。日报怎么从会话汇总，见 [从会话记录自动汇总日报](/blog/ai-workflow/daily-report-from-sessions/)。

周二推代码时 SSH 卡死。能建 TCP、能收到 banner，然后一直停在密钥交换。查下来是 `~/.ssh/config` 里有一行无条件走 SOCKS5 代理的 `ProxyCommand`，删掉就好：

```sshconfig
Host github.com
  HostName github.com
  User git
  # ProxyCommand nc -X 5 -x 127.0.0.1:7890 %h %p   # ← 删掉这一行，SSH 不再经过代理
```

系统代理不用关。浏览器和 npm 照常走代理，受影响的只有「SSH 连代码托管平台」这一条路径。排查方向应该是「哪条路径走了代理」，而不是「要不要关代理」。更多 Mac 开发机的排障，见 [Mac 开发机的日常排障](/blog/tooling/mac-dev-machine-ops/)。

## 2. 页面迁移：三页都迁完，中间两次「假完成」

第一期三页最后都迁完，推上了远端。三页是并行做的：用 git worktree 开三条隔离的线，三个 dev server 各占一个端口。三条线都要改同几个全局清单，约定新增项一律追加到末尾，冲突时两边都留。

这一周真正的事故是两次「假完成」。

**第一次（周一）**：早先的交接文档写着某一页「0%、老架构、未登记」。实测下来，它已经迁完了，只是没提交。照那份文档，下一个会话会去重做一遍。于是写了一个进度脚本，每页的状态从代码里实测，不再手写。

**第二次（周二）**：另一页交付时，进度脚本判「完成」，几十个契约测试全绿。我指出页面上的交互区还是旧版排版：给了规范，结果仍有大漏洞，不是代码报错，是需求没完成。核实下来，三道防线都放行了：

1. 进度脚本只看文件在不在（有没有接上新框架的入口、有没有登记），不看插槽里接的是新布局还是旧组件；
2. 契约测试测的是变体隔离、SEO、包体和价格口径，没有一条测排版，规范里交互区那一节零覆盖；
3. 偏离规范的理由只写在代码注释里（「插槽够不到那段布局」），没进决策日志，我没机会拍板。

修法是先造闸，再修页。先写了一个结构比对脚本，查三件事：旧页面的区块在新页面上有没有丢、目录结构和范本页差在哪、还有没有引用旧的共享组件。先在全仓已完成的页上校准，修掉 5 处会造成系统性误报的判定，做到零误报。然后拿出问题的那一页试，试出来的问题补进测试。最后做了一张 110 行的验收清单卡，留给我人判：只列肉眼能判的项，按页面从上到下排，每条附规范节号。机器能判的不重复列。

第三页也有同样的问题：第一版正文缺了 7 块，契约测试照样全绿，因为「区块齐全」没有任何机器尺。于是补了「每块都在」的断言，缺块即红。同时重写了站内链接的断言。上一版的写法是按源码文本 grep `href`，链接改成从数据派生之后，它立刻假红。断言要打在行为和数据上，不要打在源码字面上。

周二晚上我反馈「估价不随按钮变」，顺着查出一处「精确但虚构」的数字。价格计算器里有一张推理档位的「典型用量」表，数是估出来的，不是实测值，渲染出来却和真实价格一模一样。我拍板删掉，改成只算下单前能确定的部分，并写明「文本和推理 token 结算时另计」。估价固定本身是对的，缺的是一句说明。

周三 leader 把我迁过的页改了一轮。我按组逐条理解为什么改，然后追问了一句「下次怎么保证不再犯」。得到的不是一张清单，而是一个方法：一个 `await` 就是一道缝，缝的两侧，「我是谁」可能已经变了。对每道缝问三句：完成后写到哪儿，那个地方会不会变；读的是发起时的值还是最新值；这期间目的地会不会被清掉。当场拿它扫了十几个页面，扫出一个症状完全不同的问题：上传中切换变体，上传完成时会把另一档的参考图整份顶掉。详见 [一个 await 就是一道缝](/blog/frontend/async-seam-url-variant/)。

## 3. 卡住的地方

- **PR 合并的竞态**。leader 要求一次只交一个 PR。我选了把两个已开的 PR 合成一个，要做 force-push 和改描述两步，这两步不是原子的。中间同事把其中一个合进了主干，合的是 force-push 之前的版本，描述却已经改成「两件事都做了」。补救是还原描述、加勘误、关掉一个、新开一个，有一个编号永久作废。粒度要在开 PR 之前定。见 [推送和 PR 状态只问远端](/blog/git-collab/push-status-ask-remote/)。
- **调研时两次把文档当权威**。第一次把仓库里一份过时的接入规范当成正本，它写的页面路径在代码里根本不存在；第二次把上一代模型的参数名当成了新模型的。后来探测脚本的重点改成逐个发请求，用服务端的 400 反推真实参数名。
- **第一次接后端**。依赖的修复写在 `vendor/` 里能跑通，但 `vendor/` 被 git 忽略，这个改动不属于任何仓库。两个名字只差一个前缀的复刻模型，被当成了同一个模型的两种写法（最初的需求描述里也混着写），多查了约 2 小时；其实它们是官方枚举里的两个取值。上游实测的第一轮地域配错，请求全是 401，探测脚本却把 401 算成「按预期被拒」。后来加了一步免费的鉴权预检，401、403、429、5xx 一律记为出错。
- **状态没落盘**。本地部署试了好几轮，生成了一堆文档，却没写下最后一轮成没成功，第二天回溯时说不清。之后每轮尝试结束，都留一行「现在是什么状态」。

## 4. 学到的

- 测试全绿只证明尺子量到的部分。补闸的顺序是：先造闸，拿出问题的那一页试，反哺测试，最后才给人验收。见 [两次「假完成」之后](/blog/testing/fake-done-and-gates/)。
- 给人的验收物是证据包，不是文档：一页清单卡、新旧页和范本页的三栏对照、比对脚本的原始输出。迁移的完整做法见 [把旧页面迁到新页面框架](/blog/frontend/page-framework-migration/)。
- 上游探测要区分「请求没到上游」和「上游按预期拒绝」。见 [上游接口实测](/blog/model-onboarding/upstream-probe-evidence/)。
- 被 review 时追问方法，不要只拿清单。十条具体修改只能修这一页，一个能套用的方法（比如 await 三问）可以拿去扫所有页。
- dev server 和 `next build` 共用 `.next` 目录，会互相覆盖。做包体检查前先停 dev server。
- 区分「这次改动引入的失败」和「本来就红」，要有能复现的手段。这周靠它两次排除了存量失败。我现在固定这样做（细节见 [守卫测试的三个要求](/blog/testing/guard-tests-three-rules/)）：

```bash
git stash push --include-untracked -m "baseline"   # 把本分支的改动全部收起来
npm test -- --runInBand 2>&1 | tee baseline.log    # 在基线上跑一遍，记下失败的用例
git stash pop                                      # 恢复改动
npm test -- --runInBand 2>&1 | tee branch.log      # 再跑一遍，两份日志按用例名比
```

## 收尾

1. **进度从代码实测** —— 手写的进度文档过期之后不只是「有点旧」，会把人带去重做已完成的事。
2. **偏离规范进决策日志** —— 只写在代码注释里，等于没让人拍板。
3. **数字要有来源** —— 自己估的数字长得和真数字一样，用户分不出来。
4. **依赖改在源仓库** —— 在 `vendor/` 里改通了不算数。

这一周踩的坑大多是同一类：报上来的「做完了」，其实只是「量过的地方没问题」。下周起，每页交付前先跑进度脚本和结构比对，双绿了再交人判；人判的部分只留机器验不了的。
